## Question 1

**What is the creative idea behind your asset? Why did you choose this topic?**

I am building "Living Origin Cards" for a Kenyan specialty coffee roaster:
for each origin, a painterly illustration of where the coffee grows, animated
into a five second silent loop for social. I chose it because origin
storytelling is how a small roaster sells a commodity, and because a catalogue
of two hundred origins is a real batch problem rather than a one-off image, so
the unit economics actually matter.

## Question 2

**Which model did you use?**

Wan2.2-I2V-A14B (`Wan-AI/Wan2.2-I2V-A14B-Diffusers`, revision
`596658fd9ca6b7b71d5057529bbf319ecbc61d74`), image to video, 832x480, 81
frames at 16 fps, fed by an illustration drawn with Sana
(`Efficient-Large-Model/Sana_1600M_1024px_diffusers`, revision
`ac0da2ff55fbe434795be0dce883042e4d49e2fc`). Both are Apache-2.0. Sana draws
the frame, Wan2.2 animates it, and the animation is the asset.

## Question 3

**How did you run it?**

**Job.** One Nebius Serverless AI Job on one GPU: one startup, one model load
per model, ten animations back to back, and the Job stops billing when the
batch is done. Nobody waits for a single card, so there is no reason to keep a
server warm.

## Question 4

**Which GPU did you run on?**

**H100** (NVIDIA H100 80GB HBM3, `gpu-h100-sxm`, `1gpu-16vcpu-200gb`,
`eu-north1`). Wan2.2-A14B asks for at least 80 GB of VRAM, so it does not fit
an L40S.

## Question 5

**What was your generation time per asset (median), in seconds?**

**76.7 s** for the clip (81 frames at 16 fps, so 5.06 s of video). The full
pipeline per origin card is 77.5 s: 0.8 s for the illustration, 0.4 s to crop
it into the clip's frame and 76.7 s for the animation.

The median is used on purpose. The first asset of each model is a warm up and
takes several times longer, and it is paid once per run, not once per asset.

## Question 6

**What is your marginal compute cost per asset, c, in USD?**

**$0.0958** per asset, at the H100 regular price of $4.50 per GPU hour
(`c = 76.675 s x $4.50 / 3600`).

At the preemptible spot snapshot of $2.07 per GPU hour that the run was billed
at, the same marginal cost is **$0.0441** per asset.

The fixed part of the same run is **$1.5046**: 157.7 s of machine startup plus
1,046.0 s of loading the clip model, at $4.50 per GPU hour. At $2.07 it is
$0.6921.

## Question 7

**Which per call API did you compare with, and what does it charge per asset?**

**fal.ai, Wan v2.2 A14B image to video, $0.2025 per clip.**
<https://fal.ai/models/fal-ai/wan/v2.2-a14b/image-to-video>

It is the same model and the same resolution, so the comparison is about how
the work is paid for, not about output quality. fal bills video seconds by
resolution and counts 16 frames as one second: 81 frames is 5.0625 video
seconds, and the 480p rate is $0.04 per video second, so
`5.0625 x $0.04 = $0.2025` per clip.

## Question 8

**What is your self host breakeven N, in number of assets?**

**15 assets per run** at the H100 regular price of $4.50 per GPU hour.

```
N = ceil( F / (p - c) ) = ceil( $1.5046 / ($0.2025 - $0.0958) ) = 15
```

The same calculation at other prices, because the answer moves with the price:

| GPU price for H100 | `c` per asset | `F` per run | Breakeven N |
| --- | ---: | ---: | ---: |
| $4.50 regular (on demand) | $0.0958 | $1.5046 | **15** |
| $2.07 spot snapshot, 2026-11-14 | $0.0441 | $0.6921 | **5** |
| $0.79 spot price, 2026-11-23 04:11 UTC | $0.0168 | $0.2641 | **2** |
| $2.37 spot price, 2026-11-23 20:57 UTC | $0.0505 | $0.7924 | **6** |

The breakeven is decided by the fixed part, not by the marginal part, so it
moves a long way when the price of the GPU moves and barely at all when the
model gets faster.

The last two rows are the same code, the same model and the same run, sixteen
hours apart. The H100 spot price in eu-north1 went from $0.79 to $2.37 per
GPU hour and the breakeven went from 2 assets per run to 6. Quote the price
of the region you actually ran in, and date it. `mediagen spot-price` reads
the live price and prints what it does to this run:

```bash
python -m mediagen spot-price --platform gpu-h100-sxm --region eu-north1 \
  --metrics data/reference_runs/course_h100_20kids_2026-11-14.json --n 10
```

## Cost of the whole run

One Job, ten origins, from `created_at` to the last frame:

| Price regime | Run time | Run cost |
| --- | ---: | ---: |
| $4.50 per GPU hour, regular | 2,072 s | $2.59 |
| $2.07 per GPU hour, spot snapshot 2026-11-14 | 2,072 s | $1.19 |
| $0.79 per GPU hour, live spot price 2026-11-23 | 2,072 s | $0.45 |

Roughly 72% of that is the two model loads and the machine startup, which is
the number to attack before anyone thinks about making the model faster.
