## Question 1 in both sets: the creative idea

I am building "Living Origin Cards" for a Kenyan specialty coffee roaster:
for each origin, a painterly illustration of where the coffee grows, animated
into a five second silent loop for social. I chose it because origin
storytelling is how a small roaster sells a commodity, and because a catalogue
of two hundred origins is a real batch problem rather than a one-off image, so
the unit economics actually matter.

### Why these numbers

The median is used rather than the mean because the first asset of each model
is a warm up several times slower than the rest, and it is paid once per run
rather than once per asset.

The fal.ai comparison is same-model and same-resolution, so it measures how
the work is paid for rather than output quality: fal bills video seconds by
resolution and counts 16 frames as one second, which makes $0.04 per video
second at 480p times 5.0625 seconds equal to $0.2025 per clip.

The fixed part of the same run is **$1.5046**: 157.7 s of machine startup plus
1,046.0 s of loading the clip model, at $4.50 per GPU hour. At $2.07 it is
$0.6921. The breakeven follows from the two of them:

```
N = ceil( F / (p - c) ) = ceil( $1.5046 / ($0.2025 - $0.0958) ) = 15
```

The breakeven is decided by the fixed part, not by the marginal part, so it
moves a long way when the price of the GPU moves and barely at all when the
model gets faster. The same calculation at other prices, because the answer
moves with the price:

| GPU price for H100 | `c` per asset | `F` per run | Breakeven N | Cost per asset at N = 1000 |
| --- | ---: | ---: | ---: | ---: |
| $4.50 regular (on demand) | $0.0958 | $1.5046 | **15** | $0.0973 |
| $2.07 spot snapshot, 2026-11-14 | $0.0441 | $0.6921 | **5** | $0.0448 |
| $0.79 spot price, 2026-11-23 04:11 UTC | $0.0168 | $0.2641 | **2** | $0.0171 |
| $2.37 spot price, 2026-11-23 20:57 UTC | $0.0505 | $0.7924 | **6** | $0.0513 |

The last two rows are the same code, the same model and the same run, sixteen
hours apart. The H100 spot price in eu-north1 went from $0.79 to $2.37 per
GPU hour and the breakeven went from 2 assets per run to 6. Quote the price
of the region you actually ran in, and date it. `mediagen spot-price` reads
the live price and prints what it does to this run:

```bash
python -m mediagen spot-price --platform gpu-h100-sxm --region eu-north1 \
  --metrics data/reference_runs/course_h100_20kids_2026-11-14.json --n 10
```

## How the run meets the instructions

| Instruction | How this run does it | Where |
| --- | --- | --- |
| Start with what you want to create, then pick the model | The idea is fixed before the model: origin cards, so the asset is an animation of a place, and the image-to-video model that makes it is Wan2.2 | `docs/capstone-proposal.md` |
| Turn your idea into a prompt | Every prompt is built from a record, so the spreadsheet drives the asset | `src/mediagen/records.py`, `mediagen plan` |
| Generate 10 assets in one run: one startup, one model load, ten generations | One Job, one startup, one load of the model that makes the asset, and ten generations of it. Sana is loaded once as well, because the clip is image-to-video and needs a generated first frame, so the extra load is for the intermediate illustration and never for the asset. The course's own lesson 04 worker loads three models in one Job, so this is the same discipline: load once per model, never once per asset | `src/mediagen/worker.py`, `scripts/run_job.sh` |
| Use the same prompt, or ten variations of your idea | Ten variations, one prompt per origin, all sharing a style suffix so the set reads as one series | `data/origins.csv` |
| Save the assets, then stop the Endpoint or delete the DevLab | A Job stops billing when it ends. The cleanup list is in the walkthrough, including the Billing to Usage check | `docs/module-1-walkthrough.md#cleanup-and-billing` |
| Record the startup, the model load and the time for each asset | The worker times every model load and every asset, and the startup is measured from the Job's `created_at` and `started_at` and added afterwards | `mediagen annotate-startup` |
| Split them into the fixed cost per run and the cost per asset | The cost engine takes the startup and the load as `F` and the median per asset time as `c` | `src/mediagen/costs.py`, [cost-model.md](cost-model.md) |
| Use the price per hour your run paid, for your GPU and region | The live preemptible price is read from the public API for the platform and region, and the run is priced at that reading | `mediagen spot-price`, `data/prices/` |
| Project the cost per asset to N = 1000 from your run | The cost engine projects F/N + c to any N, and 1000 is one of the reported values | `mediagen report`, [cost-model.md](cost-model.md) |
| Run on a preemptible (spot) GPU when you can | The Job launcher uses a preemptible VM by default, and prints the live spot price before it creates anything | `scripts/run_job.sh` |
| Share your asset and the idea in a short post, tagging DataTalksClub and Nebius | Drafts for three channels, with the tags in them, plus the list of seven links worth posting as they happen | [learning-in-public.md](learning-in-public.md) |
| Remove all running resources when you are done, and check Billing to Usage the next day | The cleanup table and the commands are in the walkthrough | `docs/module-1-walkthrough.md#cleanup-and-billing` |

## Cost of the whole run

One Job, ten origins, from `created_at` to the last frame:

| Price regime | Run time | Run cost |
| --- | ---: | ---: |
| $4.50 per GPU hour, regular | 2,072 s | $2.59 |
| $2.07 per GPU hour, spot snapshot 2026-11-14 | 2,072 s | $1.19 |
| $0.79 per GPU hour, spot price 2026-11-23 04:11 UTC | 2,072 s | $0.45 |
| $2.37 per GPU hour, spot price 2026-11-23 20:57 UTC | 2,072 s | $1.37 |

Roughly 72% of that is the two model loads and the machine startup, which is
the number to attack before anyone thinks about making the model faster.
